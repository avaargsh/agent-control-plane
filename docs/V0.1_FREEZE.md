# v0.1 Freeze Contract

Status: **frozen v0.1.0 architecture and release contract**  
Architecture freeze date: **2026-10-02**  
Acceptance-artifact freeze: **2026-10-04**

v0.1 is intentionally a thin, evidence-first control plane. New product
abstractions are out of scope until v0.1.0 is released and exercised. The
normative release artifact set is defined in
[V0.1_ACCEPTANCE_ARTIFACT_CONTRACT.md](V0.1_ACCEPTANCE_ARTIFACT_CONTRACT.md).

## Normative execution chain

```text
project fenced execution lease
  -> fresh ObservationSnapshot
  -> TransitionPlan
  -> PlanAuthorizationBinding
  -> PlanExecutionFence
  -> durable PREPARED ExecutionAttempt
  -> provider side effect
  -> COMMITTED | ABORTED | UNKNOWN
  -> reconciliation
  -> fresh independent ObservationSnapshot
  -> VerificationReport
  -> IndependentExecutionProof
```

The LLM, Agent session, workflow history, and hidden reasoning are not authority
and are not required to verify a completed execution.

## Frozen invariants

1. **Exact-plan authority.** Authorization and execution fences bind the exact
   canonical TransitionPlan, not only a resource or operation name.
2. **Authority generation is explicit.** Provider mutation is fenced against
   stale authority generation and stale lease epoch.
3. **Authority survives the side-effect window.** A durable reservation remains
   active until the provider outcome is proven terminal; lease expiry alone does
   not release ambiguous authority.
4. **Execution is at least once.** Provider adapters must use deterministic
   identity/idempotency and must not claim exactly-once side effects.
5. **UNKNOWN fails closed.** Lost ACK, ownership ambiguity, or unverifiable
   provider state cannot be converted into success by retry policy.
6. **Observation is independent.** A provider mutation ACK is not proof of the
   desired outcome.
7. **Ownership is part of verification.** Reaching the desired state is
   insufficient when another writer may have produced it. For the Kubernetes
   reference provider, ownership is derived from a fresh observation of the
   exact operation/action/transition/plan/reservation markers.
8. **Journal identity is provider-neutral and plan-native.** Durable execution
   records bind the exact plan, authorization, fence, lease epoch, terminal
   result, and reconciliation evidence.
9. **Completed execution is independently verifiable.** Canonical artifacts can
   be serialized and verified in a fresh process without the original Agent
   session or workflow history.
10. **Authenticity is external to the proof codec.** v0.1 does not invent PKI.
    The canonical statement hash can be bound to DSSE/Sigstore/KMS or another
    trusted digest channel.

## Reference provider proofs

v0.1 proves the contract across more than one provider shape:

- Kubernetes Deployment scale transition with live kind validation,
  generation/resourceVersion fencing, independent observation, crash recovery,
  and stale/concurrent authority falsification.
- GitHub pull-request merge as a second provider proof for the same
  provider-neutral TransitionPlan / execution identity boundary.

A provider integration is acceptable only when it conforms to this contract; it
must not introduce a provider-specific authority model into the control plane.

## Required release gates

A change to the frozen execution path must keep all applicable gates green:

- Python 3.11 and 3.12 tests
- contract/schema validation
- v0.1 release gate and fresh-clone verification
- Kubernetes Transition live kind smoke
- execution fault proofs for lost ACK / crash / retry ambiguity
- stale/concurrent authority falsification
- independent proof serialization/tamper verification
- v0.1 public-surface compatibility snapshot
- Acceptance Artifact Contract validation over the complete live artifact set
- fresh-clone Kubernetes Golden Slice rehearsal and fresh-process proof verification

## v0.1 compatibility boundary

The v0.1 public compatibility promise is intentionally narrower than the source
tree. It covers the console-script names, documented CLI commands, top-level
package exports, manifest kind-to-schema mapping, and the
`IndependentExecutionProof/v1` wire identity/field names captured in
`release/v0.1-public-contract.json`.

Internal provider adapters, SQLite table layouts, coordinators, test fixtures,
and other non-exported implementation modules are not promoted to a stable
public API by this release.

`ExecutionAttestation/v2` is retained as a compatibility artifact.
`IndependentExecutionProof/v1` is the normative completed-execution release
proof.

## Explicit non-goals

v0.1 does not add:

- a new durable Agent runtime or workflow engine;
- a monolithic Transition lifecycle/orchestration state machine;
- a new policy language or approval product;
- an Agent harness, MCP gateway, sandbox runtime, or model serving layer;
- production multi-tenancy, quota/budget backends, or HA deployment;
- a new Effective Authority Diff product layer;
- a signing/PKI service.

Temporal/Restate, sandbox runtimes, policy engines, harnesses, MCP, model serving,
and signing systems remain external systems with narrow bindings.

## Change policy after freeze

Until v0.1.0 is cut, the execution core accepts only:

- correctness/security fixes;
- tests that falsify an existing invariant;
- documentation and release hardening;
- provider adapters that implement the existing provider-neutral contract without
  widening authority semantics.

New lifecycle phases, authority abstractions, orchestration layers, or product
surfaces require an explicit post-v0.1 design decision.
