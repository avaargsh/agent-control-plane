# AgentOS v3.2 Contract Baseline

AgentOS stays a thin control plane. v3.2 freezes four implementation gaps only:

1. Binding
2. Policy Projection
3. Evidence Provenance
4. Execution Contract

The control plane does not become a durable workflow runtime, sandbox runtime, vector-memory product, or universal agent RPC.

## Contract boundary

- RuntimeBinding binds Run, Session and Release identities to provider capabilities and recovery policy.
- SandboxBinding makes sandbox identity replaceable while Run and Session identity and durable state references survive.
- CapabilityIntent is portable desired authorization. policy_projection.py is the deterministic compiler seam for OpenShell, OPA, NetworkPolicy, MCP capability and credential lease targets.
- EvidenceEvent is authored outside the harness and requires generated_by, observed_by, authorized_by, executed_by and committed_by.
- ToolContract carries effect, idempotency, retry, verification and compensation semantics.
- AgentRelease can freeze CapabilityIntent references and evidence requirements.

## Integrated proofs

Three provider seams are now exercised beyond deterministic reference code:

- **Policy Projection:** CapabilityIntent compiles to Rego v1 and is evaluated by a real OPA v1.21.0 binary. The emitted SHA-256 policy digest is treated as the authorization artifact identity.
- **Binding + Evidence Provenance:** the cross-repository Golden Slice passes that exact policy digest into `cloud-agent-runtime`, preserves canonical Run/Session/Temporal identity across real Kubernetes Pod replacement, projects the digest through OTel Evidence, archives content-addressed evidence + manifest, verifies replay, and returns the digest in the terminal Temporal result.
- **Execution Contract:** a separate MCP stdio JSON-RPC provider owns persistent operation state while the contract executor proves commit-after-lost-ACK recovery, retry-after-timeout, prepared/partial-commit recovery, stable idempotency keys, post-condition failure compensation, and append-only Evidence receipts.

These proofs intentionally preserve provider ownership: OPA evaluates policy, Temporal owns durable continuation, Kubernetes owns sandbox execution, MCP providers own tool side effects, and object storage owns retention.

## Remaining provider experiments

The contract baseline still needs focused proofs for the provider surfaces that have not yet been exercised end to end:

- CapabilityIntent projection to OpenShell, Kubernetes NetworkPolicy, MCP capability enforcement and credential leases.
- SandboxBinding against a production-style Kubernetes Agent Sandbox / checkpoint provider rather than the current disposable Pod recovery proof.
- external Evidence collectors at Agent Gateway / Tool Proxy / Sandbox Supervisor boundaries with storage-side retention controls enabled.
- MCP SDK/conformance validation and a production-style durable idempotency store; the current proof intentionally exercises the stdio JSON-RPC/process boundary without claiming full SDK conformance.

These are provider integrations, not reasons to expand the control plane into a new runtime.
