# AgentOS v3.2 MCP Execution Contract Proof

This proof moves ToolContract beyond an in-process dictionary fixture while
keeping provider execution outside the control plane.

It uses a separate Python process speaking the MCP stdio JSON-RPC lifecycle:

```text
ToolContract
    |
    v
Execution adapter
    |
    | initialize
    | notifications/initialized
    | tools/call
    v
MCP stdio provider process
    |
    +--> deploy.apply
    +--> deploy.status
    +--> deploy.rollback
    |
    v
provider-owned persistent operation state
```

The provider state lives outside the client process. Killing or timing out the
MCP process therefore does not erase the idempotency record.

## Fault matrix

| Scenario | Injected failure | Contract behavior | Required invariant |
| --- | --- | --- | --- |
| lost ACK | side effect commits, provider exits before response | read-after-write | one commit, no retry side effect |
| duplicate retry | commit succeeds, ACK is lost, first status read is temporarily stale | retry the exact same key | two apply calls, one commit |
| timeout | provider blocks before commit and client kills it | verify missing, retry same key | two attempts, one commit |
| partial commit | provider persists `prepared` then exits | prepared is not success; retry same key | final commit count remains one |
| failed post-condition | apply commits but reports unhealthy | declared compensation | rollback executes exactly once |

Every scenario emits an external EvidenceEvent receipt and the append-only
evidence hash chain is verified after all five cases.

## Boundary and non-claims

This is a real process and MCP stdio JSON-RPC boundary, not an in-process fake.
It deliberately implements only the MCP methods needed by this experiment
(`initialize`, `tools/list`, and `tools/call`).

It is **not** an MCP SDK conformance claim, production deployment service, or a
reason for AgentOS to own tool-provider lifecycle. A production provider should
use an MCP SDK and its own durable idempotency/transaction store; the
ToolContract only describes the execution semantics that the control plane
requires.
