# v0.1.0 Acceptance Artifact Contract

Status: **frozen for v0.1.0 release**.

This document defines the release evidence produced by the Kubernetes
Deployment `20 -> 30` Golden Slice. The machine-readable contract is
[`release/v0.1-acceptance-artifact-contract.json`](../release/v0.1-acceptance-artifact-contract.json).

The contract exists to make one claim reproducible:

> A completed provider mutation is release evidence only when the exact
> authorized operation, durable execution identity, provider ownership,
> postcondition observation, and independent verification all close into the
> same content-addressed proof.

A provider acknowledgement or a desired state that happens to be reached is
not sufficient.

## Required artifact set

A successful `make kind-transition-smoke` run MUST produce all of:

| Artifact | Role |
| --- | --- |
| `execution-attestation.json` | v0.1 compatibility artifact; retained for existing consumers |
| `independent-execution-proof.json` | normative completed-execution proof |
| `independent-execution-proof.json.sha256` | trusted/out-of-band statement digest input for fresh-process verification |
| `execution-journal.db` | durable PREPARED/terminal execution evidence |
| `execution-leases.db` | durable execution-fence/lease evidence |
| `work-context.db` | work, authority head, proposal provenance, and authority reservation evidence |
| `summary.json` | human/CI summary of the Golden Slice result |

The SQLite files are required release evidence, but their table layouts are
**not** a v0.1 public wire-format compatibility promise.

## Normative proof chain

```text
project fenced execution lease
        |
fresh provider observation
        |
Frozen Evidence / StateTransition
        |
Policy + Approval
        |
exact TransitionPlan
        |
PlanAuthorizationBinding
        |
PlanExecutionFence
        |
durable PREPARED ExecutionAttempt
        |
provider side effect using that exact plan
        |
COMMITTED / crash reconciliation
        |
fresh independent ObservationSnapshot
        |
DesiredStateReached
+
OperationOwnershipProven
        |
VerificationReport
        |
IndependentExecutionProof
        |
serialize
        |
fresh process verification
```

The order matters. In particular, the live Kubernetes proof projects the
execution fence before freezing the provider generation/resourceVersion used by
the transition. A metadata write that changes Deployment generation must not
silently make the frozen precondition stale.

## Ownership proof inputs

For the Kubernetes reference provider,
`OperationOwnershipProven=TRUE` is derived from a **fresh provider
observation**. The following control-plane annotations are copied into
`ObservationSnapshot.state.controlPlaneOwnership` and must match the durable
execution artifacts:

- `agent-control-plane.openai.com/operation-id`
- `agent-control-plane.openai.com/action-hash`
- `agent-control-plane.openai.com/transition-hash`
- `agent-control-plane.openai.com/plan-hash`
- `agent-control-plane.openai.com/authority-reservation-hash`

The expected values come from the durable `ExecutionAttempt`,
`TransitionPlan`, and authority reservation. A missing or mismatched marker
makes ownership FALSE and the `IndependentExecutionProof` cannot be sealed.

**Desired state reached != operation ownership proven.**

A Deployment at 30 replicas can have been changed by another writer. The proof
is successful only when both the postcondition and the operation ownership are
TRUE.

## IndependentExecutionProof wire contract

For v0.1.0 the normative proof identity is:

```text
predicate_type    = agent-control-plane/state-transition-execution/v1
statement_version = independent-execution-proof/v1
```

Required top-level fields:

```text
proof_id
subject
predicate_type
predicate
statement_hash
statement_version
```

Required predicate fields:

```text
transition_plan
plan_authorization
plan_fence
execution_attempt
after_observation
verification_report
```

The verification report must contain both:

```text
DesiredStateReached       = TRUE
OperationOwnershipProven  = TRUE
```

These names and versions are part of the v0.1 public compatibility surface.

## Statement hash

`statement_hash` is computed by
`agent_control_plane.state_transition_protocol.canonical_digest` over the
`IndependentExecutionProof` object while excluding the `statement_hash`
field itself.

Canonical encoding is:

- recursive dataclass/enum/mapping canonicalization;
- UTF-8 JSON;
- `sort_keys=True`;
- `separators=(",", ":")`;
- `ensure_ascii=False`;
- `allow_nan=False`;
- SHA-256 encoded as `sha256:<lowercase-hex>`.

The separate
`independent-execution-proof.json.sha256` file is the out-of-band trusted
digest input used by the reference fresh-process verifier. v0.1 does not claim
that the hash file itself provides signer authenticity; DSSE/Sigstore/KMS or a
trusted artifact channel can bind the same digest in production.

## Fresh-process verification

Run:

```bash
python scripts/verify_execution_proof.py \
  .artifacts/kubernetes-transition/independent-execution-proof.json \
  --expected-hash-file \
  .artifacts/kubernetes-transition/independent-execution-proof.json.sha256
```

The verifier reconstructs the canonical plan, authorization, fence, terminal
attempt, fresh observation, and VerificationReport from serialized JSON. It
does not require the original Agent session, workflow history, hidden
reasoning, or execution process.

Validate the complete artifact directory with:

```bash
python scripts/verify_v01_acceptance_artifacts.py \
  .artifacts/kubernetes-transition
```

The acceptance verifier also checks the required file set, SQLite evidence
stores, summary/proof bindings, ownership markers, proof versions, and trusted
statement hash.

## Legacy ExecutionAttestation

`execution-attestation.json` remains required for v0.1 compatibility. It is
**legacy release evidence**, not the normative ownership proof.

It can bind the terminal result to independently observed outcome evidence, but
v0.1 release acceptance uses `IndependentExecutionProof` because that proof
serializes the exact `TransitionPlan`, plan authorization, execution fence,
terminal attempt, post-execution observation, and ownership-aware
VerificationReport in one independently verifiable statement.

No documentation or release gate should imply that constructing an
`ExecutionAttestation`, receiving a provider ACK, or manually setting a
verification condition to TRUE is sufficient for v0.1 release acceptance.

## Reproducibility and release evidence

The release rehearsal runs the Golden Slice from a clean local clone. On
success it writes an additional `release-evidence.json` alongside the copied
artifact set. That record contains:

- the exact source commit;
- the contract version;
- the verified IndependentExecutionProof statement hash;
- SHA-256 digests of every required artifact.

This record is CI/release evidence. It does not become another protocol object.
